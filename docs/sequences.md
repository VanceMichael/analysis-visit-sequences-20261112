# 访问序列发现与冻结复验

本文档说明 `discover` / `replay` 两个命令的口径。它们回答的问题与按区到访量不同：
到访量只描述“某区出现过多少次”，无法区分有效路径、热门展区的偶然命中与同一时刻的并行活动。

## 序列单位

- 单位是一个 buyer 的一次 `visit`；同一 `visit` 的 `buyer`、`signed`、`phase` 必须一致，否则拒绝处理。
- 同一 `tick` 的多条记录折叠为一个**无序项集**（zone 去重）。文件中同 tick 行的先后顺序不产生任何顺序语义。
- 不同 `tick` 按分钟升序，构成项集序列。同 tick 重复同一 zone 只保留一次。
- 支持度按**独立 visit**计数：一次访问内无论匹配多少遍，至多计 1。

## 模式与匹配语义

模式是“步骤数组的数组”：外层步骤严格按 tick 递增，内层是同刻出现的无序 zone 集合。
模式键用 `>` 连接步骤、用 `&` 连接同刻 zone，例如 `entrance>demo&meeting>sample`
表示 entrance 一步，之后某一 tick 同时出现 demo 与 meeting，再之后出现 sample。

一次匹配需要选出与模式等长的 tick 序列 `i_1 < i_2 < ... < i_k`，使第 j 个模式步骤的
每个 zone 都包含在第 i_j 个 tick 的项集内，并满足：

- `minGap <= t[i_j] - t[i_{j-1}] <= maxGap`（步骤间最短/最长间隔）；
- `t[i_k] - t[i_1] <= maxSpan`（全程总跨度，起点固定为首个匹配 tick）。

即使 `minGap = 0` 也不允许复用同一个 tick：同刻 zone 只能通过项集扩展并入同一步，
不能被解释成有序的两个步骤。`discover` 与 `replay` 共用 `sequences.findEmbeddings`，
两条命令的匹配语义完全一致，测试中有独立回放对照。

## 发现算法与不漏报的取舍

带 `maxGap` / `maxSpan` 后，Apriori 的支持度反单调性不再成立：不频繁的子模式可能有
频繁的超模式（子模式的匹配位置被窗口切碎，更长的模式反而落在可行窗口内）。
因此引擎**不按支持度剪枝**，只剪“零嵌入”分支——在任何 visit 都没有匹配的模式，
其任意超集也不可能有匹配，该性质在任何间隔约束下都成立。所有有嵌入的候选都会继续做
序列扩展（追加后续 tick）与项集扩展（并入末步同 tick 的其他 zone），直到 `maxLength`。

枚举由 `candidateLimit` 兜底。一旦触顶：

- 输出 `accounting.truncated = true` 与 `truncationPoint`、`truncationReason`；
- 闭合判定标注为“仅覆盖已探索候选”，明确可能遗漏未搜索到的闭合超模式；
- 绝不在截断时宣称“没有其他模式”。

`accounting.levels` 与 `accounting.screening` 给出逐层评估数、零嵌入剪枝数、
支持度筛选数与闭合筛选数，便于回答“总共探索过多少候选、如何处理多候选筛选”。

## 闭合序列表示

模式闭合，当且仅当不存在另一条模式包含它、且支持它的独立 visit 集合包含本模式的支持集
（支持集相等时，更具体的超模式使本模式成为冗余表示）。输出保留全部达到支持度的候选并
标注 `closed`，闭合项是推荐阅读的去冗余表示，非闭合项保留用于审计与展开。

## 冻结与复验

- `discover` 只在 `discoverPhase`（默认 early）上发现，结果写入冻结文件，
  含输入指纹、策略参数、候选核算与每条模式的展开证据（visit、buyer、signed、匹配 tick）。
- `replay` 通过 `--frozen` 读取冻结文件，在 `replayPhase`（默认 late）上**只回放、不重新发现**。
  冻结文件缺少输入指纹、指纹与当前输入不一致、或策略参数与冻结时不一致，都直接拒绝回放。
- 复验判定为该模式在复验场次的独立 visit 支持数是否达到 `minSupport`，并给出适用 visit 范围。
- `signed`（订单意向）只出现在 `groups` 事后描述分组中，不进入模式、匹配、支持度与判定。

## 置换基线

零假设是区域标签不携带跨刻序列信息，观测支持度只是热度与访问结构的偶然产物。
置换在每个 visit 内部重排区域标签，并严格保留：

1. visit 长度与 tick 结构；
2. 每个 tick 的同刻项集大小（交换只在互不含冲突 tick 的标签之间发生，不制造同刻重复）；
3. 每个 zone 的全局事件热度。

被破坏的只有跨 tick 的标签搭配。每次置换后都重算结构指纹并与置换前比对，
不一致即令整个基线失败而不是静默继续。输出每条模式的零分布、经验 p 值（含 +1 修正，
可分辨下限为 `1/(trials+1)`）以及只覆盖闭合模式的族级零概率。

## 结论边界

复验通过与置换基线显著，只支持“该路径值得进一步试行”并给出适用 visit 范围；
数据来自历史观察，不构成导览顺序调整带来因果提升的承诺，因果结论需要后续受控试验。
